# Spec

## R1 完整性快照必須涵蓋未追蹤檔案

快照對「工作樹中所有非 ignored 的檔案」取指紋，**不只是 tracked 檔案**。

- 審查者新增未追蹤檔案 → 必須被偵測為改動
- 審查者修改既有檔案 → 必須被偵測
- 審查者刪除檔案 → 必須被偵測
- 被 `.gitignore` 排除的路徑不納入（否則 build 產物會製造假警報）

**理由**：`git ls-files` 只列 tracked 檔案。這是本工具存在的直接原因。

## R2 工作樹不乾淨時拒絕開始

開始一輪之前，若 `git status --porcelain --untracked-files=all` 非空，**拒絕並回報**
（exit 2），不得執行審查。

**理由**：否則「審查後有改動」無法與「我自己編輯過」區分，零改動不變式失去意義。

## R3 約束區塊自動注入

每輪送出的內容 = 約束區塊 + 使用者的訊息。約束區塊由設定檔提供，內容至少包含
「不得修改本 repository」與「不得碰指定的其他路徑」。

- 設定檔缺少約束區塊 → 拒絕（exit 3）。**不得以空約束送出。**

## R4 輪次編號與歸檔

每輪產生一組成對檔案：送出的 prompt 與收到的 reply，檔名含輪次編號（三位數補零）。

- 輪次編號由既有歸檔推導，取最大值加一
- 已存在的歸檔**不得覆寫**（exit 4）

## R5 背景執行

審查可能超過十分鐘。指令送出後立即返回，不等待完成；回覆寫入歸檔路徑。
提供查詢指令回報「執行中／已完成／失敗」。

## R6 結果判定

一輪結束後自動比對前後快照並回報三種結果之一：

| 結果 | 意義 |
|---|---|
| `CLEAN` | 零改動，審查結論可信 |
| `TAMPERED` | 有改動 —— **審查結論失效，且 repository 已被污染**，列出所有變動路徑 |
| `INCOMPLETE` | 審查未正常結束，不做完整性宣稱 |

`TAMPERED` 必須以非零 exit code 結束，訊息要同時說明**兩個**後果，
不能只說「審查失效」。

## R7 唯讀沙箱不得被本工具放寬

本工具傳給審查者的沙箱參數固定為唯讀。**不提供覆寫該設定的選項。**

**理由**：一個能被旗標關掉的防線不是防線；而放寬它的人多半正是不該放寬的那個。
