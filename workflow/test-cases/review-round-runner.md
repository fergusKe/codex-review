# Test Design — review-round-runner

每條需求至少一個「壞掉時會失敗」的案例。**只證明「功能正常時會過」的測試不算數**
—— 那種測試在防線被拿掉之後照樣綠。

## R1 完整性快照涵蓋未追蹤檔案

| ID | 情境 | 動作 | 期待 |
|---|---|---|---|
| T1.1 | **新增未追蹤檔案** | 取快照 → 建立 `rogue.txt`（不 `git add`）→ 再取快照 | 兩份快照**不同**；差異列出 `rogue.txt` |
| T1.2 | 修改既有檔案 | 取快照 → 改內容 → 再取快照 | 不同，列出該路徑 |
| T1.3 | 刪除檔案 | 取快照 → 刪檔 → 再取快照 | 不同，列出該路徑 |
| T1.4 | **對照組**：完全不動 | 取兩次快照 | 相同 |
| T1.5 | gitignored 路徑 | `.gitignore` 含 `build/` → 在 `build/` 建檔 | 快照**不變**（否則 build 產物會製造假警報） |

> T1.1 是本工具存在的理由。若拿掉「涵蓋 untracked」的邏輯，T1.1 必須變紅。

## R2 乾淨工作樹前置檢查

| ID | 情境 | 期待 |
|---|---|---|
| T2.1 | 有未提交的修改時開始一輪 | exit 2，**不執行審查** |
| T2.2 | 有未追蹤檔案時開始一輪 | exit 2 |
| T2.3 | 對照組：工作樹乾淨 | 通過前置檢查 |

> T2.1/T2.2 要斷言「審查沒被執行」，不只是 exit code —— 否則把檢查移到執行之後也會通過。

## R3 約束區塊注入

| ID | 情境 | 期待 |
|---|---|---|
| T3.1 | 設定檔有約束 | 送出內容**開頭**含約束原文，其後才是使用者訊息 |
| T3.2 | 設定檔缺約束 | exit 3，不送出 |
| T3.3 | 約束為空字串 | exit 3（空約束等於沒有約束） |

## R4 輪次編號與防覆寫

| ID | 情境 | 期待 |
|---|---|---|
| T4.1 | 歸檔目錄為空 | 輪次 = `001` |
| T4.2 | 已有 `001`、`002` | 下一輪 = `003` |
| T4.3 | 已有 `001`、`003`（中間缺號） | 下一輪 = `004`（取最大值加一，不填補空缺） |
| T4.4 | **目標檔名已存在** | exit 4，**不覆寫**既有內容 |

> T4.4 要斷言原檔內容未變，不只是 exit code。

## R5 背景執行

| ID | 情境 | 期待 |
|---|---|---|
| T5.1 | 送出一輪 | 指令立即返回，不等待審查完成 |
| T5.2 | 執行中查詢狀態 | 回報「執行中」 |
| T5.3 | 完成後查詢狀態 | 回報「已完成」，且回覆已寫入歸檔 |

## R6 結果判定

| ID | 情境 | 期待 |
|---|---|---|
| T6.1 | 審查完成且零改動 | `CLEAN`，exit 0 |
| T6.2 | 審查完成但有改動 | `TAMPERED`，**非零 exit**，列出所有變動路徑 |
| T6.3 | `TAMPERED` 的訊息 | 同時說明**兩個**後果：審查結論失效 **且** repository 已被污染 |
| T6.4 | 審查未正常結束 | `INCOMPLETE`，**不做任何完整性宣稱** |

> T6.3 是訊息斷言。安全上它與 T6.2 冗餘，但使用者需要知道「還要去清理 repo」，
> 而不只是「這輪白跑了」。訊息本身就是這一層的價值。

## R7 唯讀沙箱不可放寬

| ID | 情境 | 期待 |
|---|---|---|
| T7.1 | 檢查傳給審查者的參數 | 固定含唯讀沙箱設定 |
| T7.2 | 嘗試以旗標／環境變數放寬 | **沒有任何介面能做到**（斷言 CLI 不接受該類選項） |

> T7.2 是負向能力測試：證明「做不到」，不是證明「預設不做」。

## 涵蓋範圍與邊界

- 不測 Codex 本身的行為；審查者以 stub 取代。
- 不測網路、認證、額度。
- 不判斷審查內容的正確性 —— 那是人的工作，明列為非目標。
